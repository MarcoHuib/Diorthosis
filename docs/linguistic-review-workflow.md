# Linguistic review and adjudication workflow v1

Status: implemented import/validation foundation; **zero independent human approvals**. No model selection, release approval or final held-out set. All current packets contain development-exposed material.

`dotnet src/Diorthosis.Benchmarks/bin/Release/net10.0/Diorthosis.Benchmarks.dll adjudicate <subjects.jsonl> <decisions.jsonl> <adjudications.jsonl> <NEW-report.json> [--lineage <lineage.json>]` validates bindings before writing an exclusive new report. It never changes predictions, source documents or reference files. AI votes can be retained, but cannot authorize a human adjudication. Reviewer identities, qualifications and independence are declarations; the software does not authenticate them or prove reviewer competence.

Give qualified Dutch/English reviewers **subjects.jsonl and review.html only**. Keep the separate model lineage, trace reports, analysis and this repository's model artifacts away from them until decisions are locked. The HTML has no script, remote resource or upload mechanism and escapes source text. It is a convenient offline reading/print format, not a persistence UI. Model-identifying metadata is withheld from the cards; absolute blindness cannot be guaranteed if reviewers have already seen the outputs or search the public repository. Declare that exposure.

Each review subject binds the case ID, language, layer, kind, literal source/candidate, exact annotation JSON, metadata JSON, source family/document and proposed clean flag. Hash framing is decimal UTF-8 byte length, colon, field value, repeated in that order, SHA-256. Optional candidate/family/document fields use `null` versus `string:<value>` tags, distinguishing missing from empty. Empty optional family/document IDs are rejected. Subject ID is `review-` plus the full hash. Reordered/revised annotations require new subjects. A proposal binds its selected edits and reference proposal ID, so judgments cannot transfer to another edit. Identical outputs within a layer/case are deduplicated for reviewer effort; separate lineage maps them to every contributing model. Counts of unique outputs are not independent source observations.

Each JSONL decision has these fields (copy real subject ID/hash; replace placeholders with actual declarations):

```json
{"subjectId":"review-<hash>","bindingSha256":"<hash>","reviewerId":"<actual reviewer>","reviewerKind":"human-declared","language":"dutch","qualifications":"<relevant language/review role>","independenceDeclared":true,"version":1,"judgment":{"justified":null,"meaningPreserved":null,"allDefectsRepaired":null,"noNewErrors":null,"cleanPreserved":null,"criticalSemanticFailure":null,"rejectionAppropriate":null,"acceptedAlternatives":[],"errorCategories":[],"ambiguity":"<uncertainty or none>","rationale":"<decision and evidence>"}}
```

Use `reviewerKind: "ai"` for AI assessments. Unknown boolean judgments remain null. Review case annotations first: whether input is actually clean, each error/category/span, acceptable alternatives, dependency, regional convention, source realism and ambiguity. Review proposals separately from whole passages; a correct local repair can accompany an unsafe whole passage. Preserve both reviewers' decisions even when they disagree.

After at least two distinct independent human-declared reviewers, a **separate human-declared adjudicator** records:

```json
{"subjectId":"review-<hash>","bindingSha256":"<hash>","adjudicatorId":"<actual adjudicator>","reviewerKind":"human-declared","language":"dutch","qualifications":"<relevant adjudication role>","independenceDeclared":true,"version":1,"status":"approved","reviewerVersions":{"<reviewer A>":1,"<reviewer B>":1},"judgment":{"justified":null,"meaningPreserved":null,"allDefectsRepaired":null,"noNewErrors":null,"cleanPreserved":null,"criticalSemanticFailure":null,"rejectionAppropriate":null,"acceptedAlternatives":[],"errorCategories":[],"ambiguity":"<resolved or remaining uncertainty>","rationale":"<adjudication, including disagreements>"}}
```

Statuses are `pending`, `disputed`, `approved`. Approval means approval of the adjudicated judgment, which can be negative about the correction. It does not mean the model output is correct. Identity comparison trims and ignores case. Decisions/adjudications have unique positive versions; keep history, append revisions, and re-adjudicate if a reviewer changes their decision. A stale latest approval is rejected. The import checks both reviewer versions and the subject binding. Disagreements remain visible. Unknown metric judgments are excluded from that metric's denominator; numerator, denominator, estimate and descriptive Wilson interval are emitted, along with pending/finalized coverage.

Linguistic proposal precision uses approved proposal judgments that are justified and preserve meaning. Complete-passage success additionally requires all defects repaired and no new errors. Clean preservation and critical semantic failures require their explicit passage judgments. Rejection appropriateness requires a rejection judgment. No reference match is treated as human linguistic precision. Report source-case counts separately from output-subject counts; original template families and source documents remain unknown where metadata is absent. Scenario families for new AI passages are declared scenario labels, not proof of independent origins.

To change annotations, write a new reviewed dataset version and decision manifest. Do not modify frozen sources or model predictions. Existing development and new candidates are separate collections; neither is selection nor sealed held-out material. Before final selection: recruit real qualified reviewers, adjudicate, construct genuinely unseen rights-cleared material from independent families, freeze splits/hashes, and limit access to final predictions. Targets remain 200 independently annotated errors and about 300 varied clean passages per language; current reviewed totals are zero.

With `--lineage`, imports additionally project judgments per declared model membership. The separate lineage checksum is recorded; mapping is not authenticated model identity. Shared judgments can be reused in each model report without becoming independent observations. Each metric has its own known-judgment coverage; a definitively false prerequisite is a failure even if other prerequisites are unknown.
