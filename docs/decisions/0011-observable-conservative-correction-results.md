# ADR 0011: Observable conservative correction results

Date: 2026-10-20. Status: implemented; semantic completeness is unproven.

`CorrectionResult` retains its `Edits` constructor/property and adds contract `correction-result-2.0.0`, disposition, inference termination and candidate analysis. Accepted means a deterministic proposal passed current safeguards; it does not mean independently verified linguistic correctness or final user approval. Unchanged means no proposed change. Suppressed means a cosmetic-only candidate was withheld with its reason. Rejected means incomplete, malformed, unaligned, protected-content-changing or otherwise unsafe output. NeedsReview means a detected critical clause/quotation/paragraph change cannot be authorized. Rejected and NeedsReview expose **no deliverable edits**, while diagnostic candidate text/edits remain explicitly untrusted in memory. Normal CLI JSON adds disposition/reason, omitting raw generation and diagnostic candidates. No document export is introduced.

`AnalyzeInference` is the shared termination gate, including deterministic replay; unknown/cancelled/token-limit responses cannot be recovered as complete answers. Source edits share exact UTF-16/grapheme alignment and well-formed Unicode validation. Strict structured JSON rejects extra/duplicate properties, wrong types, ambiguous insertions, overlap and oversized input. Optional literal protected spans complement heuristic token detection and allow independent edits outside those spans. Correction requests are bounded to 32768 UTF-16 units, JSON to 65536 units and 256 edits; callers must segment larger material in a separately validated workflow.

Preserve critical marker association with explicit contrast/coordination/conditional clauses, rather than only an unordered bag. Detected quotation or paragraph changes require review. Question/exclamation changes are blocked throughout the passage. These rules are conservative and can falsely flag legitimate punctuation/quotation repairs. Same-clause scope, ambiguous tense, proposition addition and many lexical meaning changes remain beyond the heuristic validator; no general semantic guarantee is claimed. Explicit spans should protect legal/factual text where known. Do not automatically salvage independent-looking hunks: dependencies are not established by a diff.

Alternatives rejected: returning an empty result without outcome; exposing raw edits as applicable suggestions; silently accepting reordered negation/modal markers; weakening protection for recall; silently overwriting benchmark outputs. Run/reparse now require distinct new output paths. CLI remains text-only and never overwrites source files.

Evidence: fake-adapter adversarial regressions plus replay of 176 saved generations. The original v4 8B `node-04` failure remains blocked (already fixed by the previous safety checkpoint). Additional rules are demonstrated on new synthetic tests, not new model-quality evidence. No raw model outputs, original annotations or historical scores are changed. Independent false-rejection and semantic judgments remain outstanding.
