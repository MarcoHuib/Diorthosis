# Hybrid spelling and document readiness follow-up

The prior [spelling feasibility study](spelling-and-future-research.md) is reused. A bounded local inspection of this repository, existing model-asset folders and the NuGet cache found no reviewed native Hunspell/Nuspell plus matching NL/EN dictionary bundle. PATH checks and exact inspected paths are recorded in [hybrid-local-inspection.json](../benchmarks/phase2/v1/hybrid-local-inspection.json). No dictionaries, packages or models were downloaded; no dependency or third-party notice was added. No dictionary-only/hybrid correction run, repair gain, overhead, memory or latency measurement is claimed.

Decision: **postpone integration because asset/license and evaluation prerequisites are absent**. The inspected historical versions are Hunspell1.7.2, OpenTaal affix header2.20.21, and moving-branch Nuspell/SCOWL disclosures; those last disclosures are not immutable reviewed asset pins. The earlier study explains their actual license choices and unresolved notices. Commercial usability alone does not satisfy the permissive-native redistribution requirement. No license exception is assumed.

Reproducible acquisition/validation plan for a later authorized asset review:

1. Create an evaluation manifest naming immutable engine source SHA, all transitive revisions, chosen license path, native build commands/compiler runtimes, six RIDs and binary hashes. Review whether the permissive-native requirement can be satisfied before acquisition or adoption; otherwise seek a compatible alternative. Record explicit legal decision and notices, not a marketing label.
2. Pin matching `.dic`/`.aff` pairs and generator sources for Dutch and separately GB/US English. Record OpenTaal/SCOWL component copyrights and generated-output provenance, exact versions, SHA-256 and licensing obligations. Never substitute an arbitrary installed dictionary.
3. Build an isolated adapter that returns untrusted candidate hints only. Verify morphology, compounds, case, Unicode and dialect behavior, cold launch without installed prerequisites, native cleanup and offline denial. Measure native/dictionary archive bytes and process memory.
4. Freeze three arms before predictions: current LLM-only; dictionary-only diagnostic alerts; same LLM/settings with dictionary hints explicitly untrusted. Include d/t/dt, participles, split compounds, separable verbs, homophones, diacritics, names, software identifiers, regional variants and varied clean technical/emails. Validator and protected spans remain authoritative.
5. Import real independent labels. Report paired gained/lost repairs, false alerts, unnecessary/unsafe proposals, contextual misses, per-case latency and sampled working set. Detection counts are not correction quality. No promotion until incremental benefit, safety and portable redistribution are demonstrated.

Context API readiness is implemented without a document parser: bounded read-only neighbors; explicit target, language, paragraph/segment IDs; immutable document revision/hash and complete request-policy hash; literal UTF-16/grapheme source mapping; defensive metadata copies; revalidation at mapping; refusal of stale identity, changed policy or inconsistent dispositions. Before/after context is explicit in the experimental prompt. Fake-adapter tests prove isolation/mapping contracts, not linguistic benefit. Two real local3B NL/EN context contract smoke checks also reached EOG, delivered the expected typo repairs, and preserved neighboring text/metadata; this does not establish a quality benefit. Real context-aware model-quality measurement is deferred because no failure-driven, independently adjudicated context panel exists; this milestone runs the justified format experiment instead of another speculative prompt comparison.

The [structural fixture design](../benchmarks/phase2/v1/context-structure-fixtures.json) covers paragraph/table/heading/list/link/header/footer/footnote/mixed-run/identifier/embedded/tracked-change boundaries. Opaque metadata is retained for review; format-run offsets are not remapped after changing text. A future exporter must implement that mapping and prove actual round trips before applying edits. No `.docx` or binary `.doc` parser/exporter or office suite dependency was added. `.doc` extraction and preservation remain separate feasibility gates. Original files are never overwritten.

Next document milestone: acquire rights-cleared complex real-format fixtures with explicit expectations for text, runs, tables, links/targets, fields, footnotes, embedded objects and tracked changes; select licensed parsers; measure extraction separately from export; compare round-trip structure visually and programmatically on Windows/macOS/Linux; fail closed on unsupported structures. No format-preserving claim follows from synthetic plain-text mapping tests.
