# Document context and segment boundaries

Status: design and deterministic mapping investigation only. No `.txt`, `.docx` or binary `.doc` parser, exporter or round-trip claim is introduced.

Future target requests should distinguish immutable neighboring context from the editable target. Provide context as encoded untrusted data with explicit labels; generated edits must address only target-local UTF-16 positions. Validate exact target text, grapheme boundaries, overlaps and all protected spans before mapping accepted proposals back to source positions. Include source revision/hash and structural location (paragraph/run/table cell/etc.) in a future document adapter; reject stale mappings. Whole-document offsets alone are insufficient for Word field/run structure. A text-element-safe segment mapper provides deterministic boundary tests without assuming sentences can be safely identified by a period regex.

Keep paragraphs and rights-cleared excerpts together when measuring context effects. Do not break identifiers, combining sequences, quotations or dependent corrections across segments. Context length is a measured runtime constraint; the current 32768 UTF-16 input bound is a safety limit, not a token-window guarantee. Token counts can exceed the 4096 context before that limit. Future context experiments must reserve prompt/output tokens using the selected tokenizer, then compare isolated target versus neighboring-context arms with exactly the same model/settings. No target-context quality inference is executed in this checkpoint.

Use explicit Dutch or English selection. Mixed technical English inside Dutch is not a translation request. Protect known terminology/quoted content, and require review for language or meaning uncertainty. No automatic language detection is adopted. Add technical mixed-language clean cases and cross-sentence tense/negation dependencies during independent annotation review.

For `.docx`, source mapping must distinguish text runs, styles, hyperlinks, fields, headers/footers, tables, lists, footnotes, comments, tracked changes and embedded objects. Preserve each by evidence-based document tests before exporting to a new destination. Legacy `.doc` requires a separately reviewed binary parser and complex real-world rights-cleared fixtures; extraction and format-preserving round trips remain separate promises. Neither a string mapper nor a model smoke test establishes either promise.
